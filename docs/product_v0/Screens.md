# Описание ключевых экранов — «Клинический компас»

**Версия:** 1.0  
**Статус:** черновик  
**Местоположение:** `docs/product/Screens.md`  
**Связь:** развивает разделы 6 и 10 ТЗ v1.0, User Story Map и Journey Map

Документ описывает ключевые экраны пользовательских интерфейсов: мобильное приложение для пациента, веб-кабинет для врача/психолога, админ-панель для клиники. Каждый экран содержит назначение, ключевые элементы, пользовательские действия и связи с гипотезами из ТЗ.

---

## 1. Мобильное приложение (пациент)

### 1.1 Экран приветствия и онбординга
**Назначение:** Первое знакомство с системой, объяснение того, что приложение не ставит диагноз, а поддерживает взаимодействие с врачом.

| Элемент | Описание |
|---------|----------|
| Заголовок | «Клинический компас — поддержка между визитами к врачу» |
| Описание | Короткий текст (2–3 предложения): «Приложение помогает вам отслеживать самочувствие и делиться этой информацией с лечащим врачом. Это не заменяет приём и не является диагнозом.» |
| Кнопка | «Начать регистрацию» |
| Ссылка | «Политика конфиденциальности», «Условия использования» |

**Связь с гипотезами:** H1 (готовность пациента к регулярному отслеживанию) — снижение барьера входа через чёткое позиционирование.

---

### 1.2 Экран регистрации с согласиями
**Назначение:** Создание учётной записи пациента с получением информированного согласия на обработку персональных и медицинских данных (152-ФЗ).

| Элемент | Описание |
|---------|----------|
| Поля ввода | Имя, дата рождения (возрастная категория), контакт для поддержки (телефон/email), пароль |
| Чекбоксы | Согласие на обработку ПД, согласие на получение уведомлений, согласие на передачу данных лечащему врачу |
| Кнопка | «Зарегистрироваться» (активна только после всех чекбоксов) |
| Индикатор | Прогресс-бар шага регистрации (1 из 3) |

**Ограничения:** Минимальный объём ввода на первом экране — пациент в депрессивном состоянии не должен испытывать когнитивной перегрузки.

---

### 1.3 Экран первичного скрининга (PHQ-9 / GAD-7)
**Назначение:** Пройти структурированный скрининг депрессии и тревоги для получения первичной оценки состояния.

| Элемент | Описание |
|---------|----------|
| Прогресс-бар | Пройдено вопросов из 16 (PHQ-9 + GAD-7) |
| Вопрос | Текст вопроса с вариантами ответов (например, «Вовсе не», «Несколько дней», «Более половины дней», «Почти каждый день») |
| Кнопка | «Далее» (активна после выбора ответа) |
| Кнопка пропуска | «Пропустить вопрос» (для снижения давления на пациента) |

**Связь с гипотезами:** H1 — пациент готов отмечать состояние регулярно; H8 — снижение «цены действия» через возможность пропуска.

---

### 1.4 Экран результата скрининга
**Назначение:** Показать первичную структурированную оценку состояния и предложить следующий шаг.

| Элемент | Описание |
|---------|----------|
| Результат PHQ-9 | Балл 0–27 с интерпретацией (минимальная/лёгкая/умеренная/тяжёлая депрессия) |
| Результат GAD-7 | Балл 0–21 с интерпретацией |
| Рекомендация | «Рекомендуем обсудить результаты с лечащим врачом», «Записаться на приём», «Продолжить наблюдение» |
| Предупреждение | «Этот результат не является диагнозом» |
| Кнопка | «Перейти к дневнику», «Показать врачу» |

### 1.5 Экран микро-отметки дневника (основной экран ежедневного использования)
**Назначение:** Быстрая отметка настроения, тревоги, сна, энергии и активности одним касанием (≤ 5 сек).

| Элемент | Описание |
|---------|----------|
| Заголовок | «Как вы себя чувствуете сейчас?» |
| Шкала настроения | 5 смайликов (от очень плохо до очень хорошо) — одно касание |
| Шкала тревоги | 5 смайликов |
| Переключатели |сон (нормально/плохо/плохо засыпаю), Энергия (низкая/средняя/высокая), Активность (ниже нормы/норма/выше нормы) |
| Текстовое поле | Опциональная заметка (до 200 символов) |
| Кнопка | «Сохранить» |

**Ограничения:** Один экран, одно действие. Голосовой ввод вместо печати — на этапе «Позднее».

**Связь с гипотезами:** H8 — снижение «цены действия» повышает приверженность; H1 — регулярное отслеживание.

---

### 1.6 Экран истории дневника с графиками
**Назначение:** Посмотреть динамику собственного состояния по неделям и месяцам.

| Элемент | Описание |
|---------|----------|
| График настроения | Линейный график по неделям (ось X — дата, ось Y — оценка 1–5) |
| График тревоги | Линейный график по неделям |
| Переключатель периода | Неделя / Месяц / 3 месяца |
| Список отметок | Последние отметки с датой, временем и примечанием |
| Кнопка | «Экспорт для врача» (PDF) |

**Связь с гипотезами:** H2 — структурированная история экономит время врача.

---

### 1.7 Экран персональной программы (назначенные упражнения)
**Назначение:** Получить от врача упражнения и материалы, отметить их выполнение.

| Элемент | Описание |
|---------|----------|
| Список упражнений | Название, тип (поведенческая активация, дневник мыслей КПТ, дыхательная практика), примерное время (5–10 мин) |
| Статус | «Не начато», «В процессе», «Выполнено» |
| Кнопка выполнения | «Отметить выполнено» после каждого задания |
| Материалы | Ссылка на рекомендованную статью/видео/аудио |
| Прогресс-бар | Процент выполнения программы на неделю |

**Связь с гипотезами:** H3 — назначение упражнений повышает приверженность плану.

---

### 1.8 Экран алертов и плана безопасности
**Назначение:** Сообщить пациенту о выявленном ухудшении и дать контакты помощи.

| Элемент | Описание |
|---------|----------|
| Уровень риска | Красный — «обязательно» (связаться с врачом незамедлительно), Жёлтый — «желательно» (обсудить на следующем визите) |
| Текст алерта | «Система зафиксировала ухудшение показателей. Рекомендуем связаться с вашим врачом» |
| План действий | Пошаговая инструкция: «1. Позвоните врачу, 2. Если не достучались — скорая помощь, 3. Контакты кризисной линии» |
| Контакты | Телефон лечащего врача, экстренная служба, кризисная линия |
| Кнопка | «Я связался с врачом», «Отложить» |

**Связь с гипотезами:** H5 — быстрый доступ к информации о безопасности; безопасность пациента.

---

### 1.9 Экран профиля и настроек
**Назначение:** Управление личными данными, уведомлениями, доступом к данным.

| Элемент | Описание |
|---------|----------|
| Персональные данные | Имя, возраст, контакт |
| Настройки уведомлений | Время напоминаний о дневнике, частота push-уведомлений |
| Доступ к данным | Какие врачи имеют доступ к дневнику, отозвать доступ |
| Кнопка | «Выйти из аккаунта» |

## 2. Веб-кабинет (врач / психолог)

### 2.1 Дашборд врача (главный экран)
**Назначение:** Обзор пациентов, требующих внимания, и алертов.

| Элемент | Описание |
|---------|----------|
| Список пациентов | ФИО, дата последнего визита, статус (стабильно/требует внимания/критично) |
| Алерты | Красный индикатор у пациентов с критическими симптомами, количество непрочитанных алертов |
| Быстрые действия | «Создать карточку пациента», «Посмотреть отчёты перед визитами» |
| Фильтры | По отделу, по врачу, по уровню риска |

**Связь с гипотезами:** H2 — структурированная история сокращает время подготовки к визиту.

---

### 2.2 Карточка пациента
**Назначение:** Единое клиническое представление о пациенте: анамнез, скрининги, динамика, назначения.

| Элемент | Описание |
|---------|----------|
| Блок персональных данных | Имя, возраст, дата регистрации, лечащий врач |
| Результаты скринингов | История PHQ-9/GAD-7 с датами прохождения |
| Дневник пациента | Графики настроения, тревоги, сна, энергии за выбранный период |
| Назначенные упражнения | Список активных и завершённых назначений со статусом выполнения |
| История визитов | Даты приёмов, краткие выписки, корректировки плана лечения |
| Кнопки | «Назначить упражнение», «Создать отчёт», «Отправить сообщение» |

---

### 2.3 Экран назначения упражнений и материалов
**Назначение:** Врач назначает пациенту упражнения по КПТ и поведенческой активации.

| Элемент | Описание |
|---------|----------|
| Выбор пациента | Из списка пациентов врача |
| Каталог упражнений | Фильтр по типу (поведенческая активация, дневник мыслей, релаксация), по сложности |
| Настройки назначения | Частота (ежедневно/через день/еженедельно), срок начала и окончания, комментарий для пациента |
| Кнопка | «Назначить» (отправляет уведомление пациенту) |

---

### 2.4 Экран отчёта о динамике перед визитом
**Назначение:** Структурированная выгрузка данных пациента для подготовки к повторному приёму.

| Элемент | Описание |
|---------|----------|
| Сводка за период | Средний балл PHQ-9/GAD-7, тенденция (улучшение/ухудшение/стабильность) |
| Дневник | Графики с выделением дней пропуска отметок |
| Упражнения | Процент выполнения назначений |
| Алерты | Количество и типы срабатываний системных предупреждений |
| Кнопка | «Сформировать PDF-отчёт», «Добавить свои комментарии» |

**Связь с гипотезами:** H2 — экономия времени врача на приёме.

---

### 2.5 Экран корректировки плана лечения
**Назначение:** Врач документирует решение на основе данных системы и корректирует план.

| Элемент | Описание |
|---------|----------|
| Текущий план | Список активных назначений (лекарства, упражнения, рекомендации) |
| Изменения | Добавить/удалить/изменить назначение, комментарий к изменению |
| Подтверждение пациентом | Флаг «Согласовано с пациентом» (не автоматически — только после обсуждения) |
| Кнопка | «Сохранить план», «Отправить пациенту» |

**Ограничение:** Система не принимает клинических решений автоматически — только поддерживает принятие решения врачом.

---

### 2.6 Экран инструкций ГРЛС / фармакологических препаратов
**Назначение:** Быстрый доступ к актуальной информации о препаратах (включая «Авиандр» / маритупирдин из case_info).

| Элемент | Описание |
|---------|----------|
| Поиск препарата | По названию или МНН |
| Карточка препарата | Торговое название, МНН, форма выпуска, дозировка, показания, противопоказания, режим дозирования, побочные эффекты |
| Предупреждения безопасности | Категории «обязательно» / «желательно» при одновременном приёме с другими препаратами |
| Ссылка | «Источник: ГРЛС» с датой обновления |

**Связь с гипотезами:** H5 — врачу нужен быстрый доступ к фармакологической информации.

## 3. Админ-панель (администратор клиники / суперадминистратор)

### 3.1 Панель управления ролями и правами
**Назначение:** Назначение ролей сотрудникам клиники и разделение доступа к контурам.

| Элемент | Описание |
|---------|----------|
| Реестр сотрудников | Имя, роль (врач, психолог, координатор, администратор), статус (активен/заблокирован) |
| Назначение ролей | Выпадающий список ролей с описанием прав доступа |
| Разделение контуров | Переключатель доступа к общему контуру и рецептурному контуру (concept02) |
| Кнопка | «Применить изменения», «Сбросить пароль» |

---

### 3.2 Дашборд аналитики клиники
**Назначение:** Агрегированная аналитика по отделениям и врачам.

| Элемент | Описание |
|---------|----------|
| KPI карточки | Screening Completion Rate, Activation Rate, Weekly Check-in Rate, Care Plan Adherence |
| График активности | Количество активных пациентов и врачей по неделям |
| Отчёт по алертам | Количество срабатываний, время реакции врача |
| Экспорт | CSV / PDF для руководства клиники |

**Связь с гипотезами:** H4 — клиника ценит мониторинг между консультациями.

## 5. Навигационная схема (текстовая)

```
Пациент:
  Приветствие → Регистрация → Скрининг → Результат скрининга
       ↓                          ↓
  Дневник (микро-отметка) ←───────┘
       ↓
  История дневника с графиками
       ↓
  Персональная программа (упражнения)
       ↓
  Алерты и план безопасности (при срабатывании)

Врач:
  Дашборд → Карточка пациента → Отчёт о динамике
       ↓              ↓              ↓
  Назначение упражнений  Корректировка плана
       ↓              ↓
  Инструкции ГРЛС ←───────────────────┘

Админ клиники:
  Управление ролями → Дашборд аналитики
```
