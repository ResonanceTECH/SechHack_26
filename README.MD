# SechHack_26 - Клинический компас

Система помощи принятия врачебных решений (цифровой ассистент врача) для ведения пациентов с тревожно-депрессивной симптоматикой. Мультиплатформенное решение: веб-кабинет для врачей, мобильное приложение для пациентов, интеграции с медицинской информационной системой и службами неотложной помощи.

Решение разработано в рамках междисциплинарного кейс-чемпионата [«Клинический компас»](https://clinicalcompass2026.ru/)

## 1. Назначение

### Для кого

| Роль | Что даёт |
|------|----------|
| **Врач / Психиатр / Психолог** | Веб-кабинет: панель пациентов, карточка пациента, опросники (PHQ-9, GAD-7, YMRS и др.), дневник самооценки, назначение лекарств и упражнений, чат с пациентом, оповещения и кризисные сигналы, расписание приёмов, отчёты перед визитом |
| **Пациент** | Мобильное приложение: регистрация через телефон + СМС-код, ежедневный дневник настроения/тревоги/энергии, прохождение опросников, уведомления о приёме лекарств, чат с врачом, план безопасности, дыхательные упражнения, экстренная помощь |
| **Координатор / Администратор клиники** | Управление сотрудниками, настройка клиники, просмотр аналитики, журналы аудита, приглашение специалистов |

### Ключевые пользовательские сценарии

1. **Пациент**: Регистрация (телефон → СМС → согласия 152-ФЗ → код приглашения врача) → ежедневный дневник настроения → прохождение опросников → получение уведомлений о лекарствах → чат с врачом → экстренная помощь
2. **Врач**: Панель пациентов → карточка пациента (демография, диагнозы, опросники, дневник, лекарства) → назначение плана лечения → ответ на оповещения → просмотр отчёта перед визитом → чат → расписание
3. **Администратор**: Приглашение сотрудников → настройка ролей → просмотр аналитики клиники → аудит действий

### 2.2 Поток запроса

1. **Mobile**: React Native → HTTP → FastAPI (JWT auth) → PostgreSQL (PHI data) → Response
2. **Web**: React → HTTP → FastAPI (JWT auth) → PostgreSQL → Response
3. **Integrations**: FastAPI → MIS/Emergency adapters → External systems (FHIR mapping)
4. **Background**: Redis (rate limit) → Celery (запланировано, не реализовано)

## 4. Быстрый запуск

Полный стек (Postgres + Redis + Backend):

```bash
git clone <repo-url> SechHack_26
cd SechHack_26

# Настройка .env
cp backend/.env.example backend/.env
# Отредактируйте SECRET_KEY и другие переменные

# Запуск
docker compose up -d

# Миграции БД
cd backend
alembic upgrade head

# Начальные данные (опционально)
python seed.py

# Запуск серверной части
uvicorn app.main:app --reload --port 3001
```

Сервис | URL
-------|----
Backend API | http://localhost:3001
Swagger Docs | http://localhost:3001/docs
Health | http://localhost:3001/health
Postgres | `localhost:5432` (user/pass/db: из .env)
Redis | `localhost:6379`

Остановка:
```bash
docker compose down
# с данными БД:
docker compose down -v
```

### Мобильное приложение (пациенты)

| Роль | Телефон | Пароль | Код приглашения |
|------|---------|--------|----------------|
| Пациент | +79991234567 | (задаётся в seed.py) | RAV27400 |

**Код приглашения**: `RAV27400` — связывает пациента с врачом-психотерапевтом (Ivan Petrov)

### Настройка паролей

Для установки реальных паролей используйте эндпоинт смены пароля:

```bash
# Смена пароля для врача
curl -X POST http://localhost:3001/api/v1/auth/change-password \
  -H 'Authorization: Bearer <access_token>' \
  -H 'Content-Type: application/json' \
  -d '{"old_password":"hashed_password","new_password":"новый_пароль"}'
```

Или отредактируйте файл `backend/seed.py` и замените `"hashed_password"` на реальные хеши паролей (Argon2id), затем выполните:
```bash
cd backend
python seed.py
```

## Ключевые фишки и чем выделяемся

### 1. Клиническая строгость
- **8 валидированных опросников**: PHQ-9, GAD-7, YMRS, HCL-8, HCL-33, C-SSRS, PDSS, ISI — все с источниками из клинических рекомендаций Минздрава РФ
- **Серверный подсчёт баллов**: клиент не может влиять на результат
- **Критические результаты**: автоматическое определение суицидального риска (C-SSRS, PHQ-9 п.9)
- **Версионирование опросников**: поддержка разных версий шаблонов

### 2. Мультиплатформенность
- **Веб-кабинет врача**: React 19 + Vite, 20+ экранов, полный функционал
- **Мобильное приложение пациента**: React Native + Expo, 48 экранов, офлайн-поддержка дневника
- **Единый API**: один FastAPI-бэкенд для всех клиентов

### 3. Безопасность и приватность
- **152-ФЗ**: обязательные согласия на обработку персональных и медицинских данных
- **RBAC**: 6 ролей (patient, doctor, psychologist, coordinator, clinic_admin, super_admin), deny-by-default
- **RLS (Row-Level Security)**: изоляция данных между клиниками на уровне БД
- **Журналы аудита**: запись всех действий (без паролей и токенов)
- **Argon2id**: хеширование паролей с параметрами `time_cost=3, memory_cost=64 MiB, parallelism=4`
- **JWT rotation**: refresh-токены одноразовые, повторное использование → отзыв всех сессий
- **Rate limiting**: защита от брутфорса (5 попыток входа за 15 мин), СМС-spam (1 СМС в 60 сек)

### 4. Клиническая изоляция
- **Multi-clinic**: поддержка нескольких клиник в одной БД
- **Practitioner clinic memberships**: врач может работать в нескольких клиниках
- **RLS для PHI**: все таблицы с персональными данными защищены на уровне БД
- **Cross-clinic тесты**: негативные тесты подтверждают изоляцию

### 5. Интеграции
- **MIS интеграция**: pulling/pushing пациентов, опросников, оповещений
- **Emergency Services**: кризисные сигналы → внешние системы
- **FHIR R4 mapping**: `Observation` из результатов опросника
- **Webhook processing**: приём событий от внешних систем
- **Idempotency**: предотвращение дублирования при интеграции

### 6. Продвинутый дневник
- **5 шкал**: mood (-3..+3), anxiety (0..4), energy (0..4), functioning (0..4), sleep
- **Офлайн-синхронизация**: массовая синхронизация с дедупликацией по `(device_id, recorded_at, patient_id)`
- **Versioning**: история изменений записей, addendum
- **CHECK-ограничения**: защита от некорректных значений на уровне БД

### 7. Лекарства и рецепты
- **Справочник препаратов**: торговое название, МНН, дозировка, форма выпуска
- **Сокращённый/полный контур**: пациент видит только инструкции, врач — противопоказания и взаимодействия
- **Adherence tracking**: отметки приёма, расчёт соответствия
- **Корректировка**: возможность исправить ошибочно пропущенный приём с аудитом

### 8. Оповещения и кризис
- **Правила оповещений**: автоматическое создание по опросникам
- **Приоритеты**: mandatory (с планом безопасности), optional, rx
- **Кризисные сигналы**: manual, screening_result, system
- **План безопасности**: структурированный JSON с шагами и контактами

### 9. Чат и расписание
- **Чат пациент-врач**: сообщения, состояние прочтения
- **Уровень доступности**: расчёт `is_available_now` и `next_available_at` по расписанию
- **Расписание врачей**: регулярные интервалы, исключения
- **Timezone клиники**: IANA timezone для корректного расчёта

### 10. Упражнения и планы ухода
- **Care Plans**: планы ухода с упражнениями
- **Exercise assignments**: назначение врачом, выполнение пациентом
- **Compliance**: расчёт adherence по упражнениям
- **Автосоздание**: default care plan при назначении упражнения без плана

### 11. Аналитика и отчёты
- **Отчёт перед визитом**: агрегат данных пациента (опросники, дневник, лекарства)
- **Аналитика клиники**: JSON-агрегаты по пациентам, оповещениям, опросникам
